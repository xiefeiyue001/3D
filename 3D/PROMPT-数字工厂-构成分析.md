## 一、整体骨架

这份提示词不是"描述想要什么效果"，而是**把一份工程说明书当成提示词写**。它做了三件事：

1. 先把**验收标准**钉死（第 1、11 节），让"做没做完"变成可判定的事实；
2. 再把**视觉方向**钉死到色板、比例、字体、后处理层面（第 2 节），消灭"AI 味"的自由发挥空间；
3. 最后把**执行细节**拆成可复现的坐标系、时间轴、镜头表（第 3、4、8、9 节）。

13 节的分工可以归成四组：

| 组 | 节 | 作用 |
| --- | --- | --- |
| 交付定义 | 1 目标与交付物、12 交付清单 | 产物是什么、由哪些文件构成、怎么构建 |
| 审美定义 | 2 视觉方向、3 场景总图 | 长什么样、世界有多大、哪里剖切 |
| 系统定义 | 4 模拟系统、5 数据层、6 HUD、7 交互 | 场景怎么"活"起来、怎么被读、怎么被操作 |
| 呈现定义 | 8 电影级巡游、9 相机与光学、10 性能预算、11 验收清单、13 拆分建议 | 怎么拍、怎么算力可控、怎么验、怎么分工 |

## 二、逐节拆解（它到底规定了什么）

**1 目标与交付物**
规定单文件 `digital-factory-3d.html`、three.js r160 内联、一切几何程序化生成（不许外部模型/贴图），并把实现拆成 `src-df/10-util.js … 90-boot.js` + `shell.html` + `build-df.js` + QA 脚本。这一节的价值在于**把"单文件"和"可维护"这对矛盾用构建脚本化解**：源码分片开发，产物仍是一个 HTML。

**2 视觉方向**
给出的是"摄影棚 + 实体工厂 + 琥珀数据层"的三层结构，并把色板写成 4 个 hex：`#060708` 底色 / `#f2a73b` 琥珀 / `#9ed6b4` 青绿 / `#ff5638` 告警红。更关键的是**真实比例清单**：人 1.75 m、车 4.6×1.86×1.46 m、挂车 13.6 m、厂房 156×80×15.8 m。比例一旦写死，"看起来像玩具"的问题就从根上被掐掉。

**3 场景总图**
用**坐标区间**描述世界：x∈[-78,78]、z∈[-40,40]。再用"剖切规则"规定哪面墙满高、哪面切到 7.5 m、南侧只留 1.2 m 女儿墙、无屋面板只有桁架。这一节的写法值得抄：不描述"好看的视角"，而是描述**建筑做法**，让模型自己长出正确的剖面。随后用 Z01–Z07 七个分区表格把工艺段落落位。

**4 模拟系统**
把工厂变成一个**有状态的系统**：21 工位、58 s 节拍、双线 124 台/h、白班 08:00–20:00、初始时刻 14:36、产量 936/1488、OEE=A×P×Q、故障 6–15 s、WIP、能耗 1.2–1.3 MW、AGV 车队、96 点历史、8× 仿真时钟与 1×/2×/4× 演示速率。这些数字合起来的意义是：**HUD 上的每个数都能被推导**，不是随机数。这是"数字孪生感"的真正来源。

**5 数据层**
把"看不见的东西"分层列清：6 个分区轮廓、DOM 投影标签（20 fps 限速）、能源流、物料流、扫描带、包络盒、信标、选中高亮。注意它规定了**DOM 标签的刷新率**和**避让规则**——这是把 UI 性能写进提示词的典型手法。

**6 HUD**
按屏幕区域罗列：顶栏、左分区索引、右 KPI、底部 dock、图签、罗盘、开场 veil、移动端。等于给了张"界面施工图"，避免生成一堆装饰性面板。

**7 交互**
拖拽/缩放/拾取/分区导航/设备聚焦，加**快捷键表**（1–6/0/L/D/Space/H/B/F/Esc），加 **URL 参数清单**（`?film=1`、`?tour=1`、`?instant=1` 等）。URL 参数这一条尤其重要：它让"纯净录屏""直接跳到巡游第 N 秒"变成可复现的验收动作。

**8 电影级巡游**
是全篇最"像导演"的一节：总 88.5 s、9 章分镜表，每段给 `tx,ty,tz,azim,elev,dist,fov`、`split`（一段拆两段缓入+漂移）、a/b 关键帧、无缝回环。**用数值写运镜**，而不是"镜头缓缓推进"。

**9 相机与光学**
默认 `tx=4, ty=3, tz=2, azim=-0.70, elev=0.44, dist=300, fov=29`。一个球坐标相机加上限位（极角、距离、fov），保证任何角度都是成立的构图。

**10 性能预算**
<400 draw calls、<1.2 M triangles，并给出参考值 271 calls / 291k tris。写死预算之后，"加细节"就必须走合并几何与实例化。

**11 验收清单**
6 条可勾选项（能离线打开、无双屏、60 fps、巡游可循环、点击有反馈、录屏无 HUD）。这是把主观评价转成客观勾选。

**12 交付清单**
文件级清单：HTML、README、源码分片、构建脚本、QA 截图。

**13 多 Agent 拆分建议**
把 13 节映射到多个执行体（建模/系统/数据/HUD/巡游/QA），说明这份提示词本身是**为多 Agent 协作设计**的。

**最短版本**
一句话把全部约束压成一句，用于快速对齐。

## 三、可复用的写法（7 条）

1. **坐标化**：不写"一个大厂房"，写 `x∈[-78,78]`、`h=15.8`。模型不需要猜，也不需要问。
2. **比例尺**：把人体、车辆、建筑的真实尺寸列出来，是廉价而有效的"去玩具化"手段。
3. **剖面规则**：用建筑做法（哪堵墙多高、有没有屋面板）代替"取景角度"，解决剖切视角下模型穿帮。
4. **状态化数字**：产量、节拍、OEE、WIP、能耗互相自洽，HUD 才有可信度。
5. **运镜写数值**：`azim/elev/dist/fov` 四元组 + 时长 + 拆分方式，比形容词可执行。
6. **URL 参数**：把"录屏、跳章节、隐藏 HUD、快速启动"变成可复现的开关。
7. **预算与验收**：draw call/三角面上限 + 勾选清单，倒逼实现方式。

## 四、这套结构能复用到哪

它的通用骨架是**「交付定义 → 审美定义 → 系统定义 → 呈现定义」**，只要把"工厂"换掉，就能复刻到任何"大体量、多工序、要巡游"的三维题材：航天火箭总装与发射、港口码头、机场航站楼、数据中心、炼化装置、汽车试验场、水厂、地铁车辆段。
